# 架构概览

本文档详细描述 rho-aias 的系统架构和各组件的协作方式。

## 整体架构

rho-aias 采用分层架构设计，主要分为三个核心层：

```
┌───────────────────────────────────────────────────────┐
│                    管理层 (Manager)                     │
│  ┌─────────┐  ┌──────────┐  ┌───────────┐            │
│  │ REST API │  │ 规则引擎  │  │ CLI 工具  │            │
│  └────┬────┘  └────┬─────┘  └─────┬─────┘            │
│       │            │              │                    │
│  ┌────┴────────────┴──────────────┴─────┐             │
│  │           认证授权 (RBAC)             │             │
│  │     JWT / API Key / Casbin          │             │
│  └────────────────┬────────────────────┘             │
├───────────────────┼──────────────────────────────────┤
│                   │  用户态 (Userspace)                │
│  ┌────────────────┴────────────────────┐             │
│  │            eBPF Manager              │             │
│  │  ┌──────────┐ ┌───────────────────┐ │             │
│  │  │规则同步器│ │  状态收集器       │ │             │
│  │  └────┬─────┘ └────────┬──────────┘ │             │
│  └───────┼───────────────┼─────────────┘             │
├──────────┼───────────────┼───────────────────────────┤
│          │    内核态 (Kernel Space)                   │
│  ┌───────┴───────────────┴───────┐                   │
│  │        XDP eBPF Program        │                   │
│  │  ┌─────────┐  ┌─────────────┐ │                   │
│  │  │ 包解析器│  │  规则匹配器  │ │                   │
│  │  └─────────┘  └─────────────┘ │                   │
│  │  ┌─────────┐  ┌─────────────┐ │                   │
│  │  │ 白名单  │  │  统计计数器  │ │                   │
│  │  └─────────┘  └─────────────┘ │                   │
│  └────────────────────────────────┘                   │
├──────────────────────────────────────────────────────┤
│              网络接口 (Network Interface)               │
│                  eth0 / ens192                        │
└──────────────────────────────────────────────────────┘
```

## 数据流

```
网络数据包到达
     │
     ▼
┌─────────┐
│  网卡   │ ── 数据包进入网卡驱动
└────┬────┘
     │
     ▼
┌─────────────────┐
│ XDP Hook Point  │ ── eBPF 程序在协议栈之前执行
└────┬────────────┘
     │
     ▼
┌─────────────────┐     匹配白名单     ┌──────────┐
│  IPv4/IPv6 解析  │ ────────────────▶ │ XDP_PASS │ (放行)
└────┬────────────┘                    └──────────┘
     │
     │ 未匹配白名单
     ▼
┌─────────────────┐     匹配封禁规则   ┌──────────┐
│   规则匹配       │ ────────────────▶ │ XDP_DROP │ (丢弃)
└────┬────────────┘                    └──────────┘
     │
     │ 未匹配任何规则
     ▼
┌─────────────────┐
│ XDP_PASS        │ ── 交给内核协议栈继续处理
└─────────────────┘
```

## 核心组件

### eBPF XDP 程序（内核态）

负责实际的数据包过滤，运行在内核空间：

- **包解析器**：解析 Ethernet/IP/TCP/UDP 头部
- **规则匹配器**：基于 eBPF Map 存储的规则进行匹配
- **白名单**：优先检查白名单，确保受信流量不被拦截
- **统计计数器**：记录通过和丢弃的数据包数量

### eBPF Manager（用户态）

负责用户态和内核态之间的通信：

- **规则同步器**：将用户态的规则变更同步到 eBPF Map
- **状态收集器**：从 eBPF Map 读取统计信息和运行状态
- **程序加载器**：编译和加载 eBPF 程序到内核

### 规则引擎

管理所有防火墙规则的完整生命周期：

- 规则的 CRUD 操作
- 多源规则聚合（手动、威胁情报、GeoIP）
- 规则冲突检测和优先级排序
- 规则过期清理

### 认证授权

基于 Casbin RBAC 的细粒度权限控制：

- **JWT 认证**：用户登录获取 Token
- **API Key**：服务间调用的简化认证
- **RBAC**：基于角色的访问控制（admin, operator, viewer）

## eBPF Map 结构

| Map 名称 | 类型 | 用途 |
|---------|------|------|
| `block_ips` | `BPF_MAP_TYPE_HASH` | 封禁 IP 列表 |
| `block_cidrs` | `BPF_MAP_TYPE_LPM_TRIE` | 封禁 CIDR 列表 |
| `allow_ips` | `BPF_MAP_TYPE_HASH` | 白名单 IP 列表 |
| `stats` | `BPF_MAP_TYPE_PERCPU_ARRAY` | 包计数统计 |
| `config` | `BPF_MAP_TYPE_ARRAY` | 运行时配置 |
